# DynoPay Deep Audit — June 2026 (this fork)

Scope: backend (Node/Express/TS), frontend (Next.js), integrations, DB, Redis. User asked:
"deep analysis for missed bugs, improve, cleaner code, high performance". Approved: full sweep,
fix everything, archive root clutter to /app/_archive, full testing_agent regression.

## Fixed (ranked by severity)

### P0 — Security
1. **OTP brute-force (account takeover)** — `POST /api/user/verify-email` (passwordless login for
   existing accounts), forgot-password verify, contact-email verify, password-change OTP, onboarding
   OTP had NO per-code attempt cap; only a racy IP-scoped rate limiter. Added `helper/otpGuard.ts`
   (`recordOtpFailure` → 5 strikes then code deleted, TTL preserved) and wired into 6 verify sites.
   Verified end-to-end: 4× "Invalid OTP" → 5th "Too many incorrect attempts" → code gone.
2. **Predictable OTPs** — 12 sites used `Math.random()` for 6-digit codes. Now `crypto.randomInt`
   via `generateOtpCode()`.
3. **SSRF via merchant webhook URLs** — only a `localhost` string check existed. New
   `utils/outboundUrlGuard.ts` (scheme + literal IP + DNS-resolved private-range checks, blocks
   169.254/10/172.16/192.168/127/::1/*.internal) applied in `webhooks/index.ts` before delivery and
   in `PUT /company/webhook-settings/:id` at save time. `axios.post` now `maxRedirects: 0`,
   `maxContentLength: 1MB`.
4. **OTP leak in logs** — `controller/wallet/withdrawals.ts` logged `req.body` + stored OTP at info.

### P1 — Correctness / reliability
5. **Distributed lock stale-cleanup deleted peers' locks** — `cleanupStaleLocks()` (run on every
   boot) treated any PID not alive on *this host* as dead → a booting web replica/worker would delete
   the cron lock held by a live peer (double sweeps/settlements). Lock value is now `host:pid:ts`,
   cleanup only touches same-host locks, uses SCAN instead of KEYS. Renewal-timer code deduped.
6. **Rate limiter**: non-atomic GET/SET (burst bypass) and keys written WITHOUT TTL (274 permanent
   `ratelimit:*` keys in prod Redis). Rewritten as one atomic Lua sliding-window ZSET with PEXPIRE;
   API keys hashed (sha256) instead of raw in key names; single `clientIp()` helper.
7. **Redis leak**: `pending-notif-*` / milestone / partial markers set without TTL (445 permanent
   keys in prod). Now 30-day TTL. NOTE: `customer-*` sessions are the persistent payment-link store
   (checkout loads from them) — deliberately NOT given a TTL.
8. **Express error handler** lacked `res.headersSent` guard; unknown `/api/*` routes returned HTML
   ("Cannot GET") — now JSON 404.
9. **FastForex** subscription is lapsed ("No active subscription") → every fiat conversion paid a
   failed ~300ms round-trip before Tatum fallback. Added 30-min circuit breaker on 401/402/403/429/
   subscription errors. (User action: renew or remove FASTFOREX key.)

### P1 — Database performance (prod, applied via boot migrations 0021/0022)
10. **1,093 duplicate unique indexes** (Sequelize `alter:true` bug): tbl_publishable_key ×789,
    tbl_user/tbl_referee_code/tbl_kb_* ×75 each. Dropped, keeping one per definition (FK deps only
    target `_pkey`). Index count 1,323 → 230, ~16MB reclaimed, writes no longer touch 790 indexes.
11. **Missing hot-path indexes** (pg_stat idx_scan=0): added on tbl_user_transaction (user/company +
    createdAt, wallet, status), tbl_customer_transaction, tbl_notification, tbl_user_wallet,
    tbl_payment_link, tbl_company.user_id, tbl_user_addresses, tbl_kyc, tbl_api.user_id, tbl_user.email.

### P2 — Frontend
12. `kyc/status` fetched 3× per dashboard load via 3 different SWR keys → single `hooks/useKycStatus.ts`.
13. `CompanyDataContext`/`WalletDataContext` created a fresh `[]` each render when data undefined
    (memo/effect churn) → stable memoized list.
14. `axiosConfig.ts` console.log on every load removed.

### Cleanup
15. 130+ stray files (ad-hoc test scripts, PNGs, log reports, planning docs) moved to `/app/_archive/`
    (excluded in tsconfig + .dockerignore). Backend root `test_*.ts/.cjs` were being compiled into
    dist → archived. Unused `backend/package-lock.json` archived (yarn is canonical).
16. Module-level housekeeping intervals `.unref()`'d (botProtection, slackAlertService).

## Found but NOT changed (report to user)
- Money math is float-based (`parseFloat`/`toFixed`, 63 sites in settlement) — decimal.js refactor is
  a large project; current tolerances mask it. P2 architectural.
- `sanitizeInput` middleware HTML-escapes `<`/`>` in every string field (e.g. "Orders < $50" stored
  as `&lt;`). React escapes output anyway; low impact.
- `next.config.mjs` images.remotePatterns hostname `**` → Next image optimizer is an open proxy
  (bandwidth abuse). Merchants paste arbitrary product image URLs, so left as is.
- 78 `react-hooks/exhaustive-deps` warnings — nearly all intentional mount-only effects; blanket
  fixing risks loops.
- `express.json({limit:'10mb'})` is generous; uploads use multer. Left.
- Pod→Railway DB RTT is ~180ms here (prod is same-region); endpoint latency in preview is RTT-bound,
  not query-count-bound (2–8 queries/endpoint measured).
- Pre-existing failing jest suites: ledgerPaymentMapper (missing dbInstance mock), adminFlows /
  realTimeEvents / paymentWalletFlows (need admin creds/env). Not production bugs.
- Leaked legacy Redis keys still present in prod DB0 (old `ratelimit:*:json`, `pending-notif-*`
  without TTL) — cleaning them is a prod write; script idea: EXPIRE them. Left for user approval.

# Follow-up session (same fork) — user-approved items

## CRITICAL (found while wiring alerts, fixed + verified live)
- **Password-reset account takeover**: `POST /api/user/reset-password` treated `getRedisItem()`'s `{}`
  (returned for a MISSING key) as a valid OTP session and fell back to the request-body `email`
  → any account's password could be reset with a made-up token, no OTP. Fixed in
  `controller/user/passwordReset.ts` (`hasOtpSession` requires session.email/userId; body email
  never used). Verified: bogus token → "Invalid or expired reset token"; legit OTP → single-use
  token → body email ignored; login unaffected. Same `{}`-truthiness bug fixed in
  `exchangeConfirm.ts` (OTP compare) and `chainVerification.ts` (junk `customer-*` writes).
  LESSON: `getRedisItem()` returns `{}` when absent — always check a real field.

## Redis cleanup (prod DB0) — APPLIED
- `scripts/audit/redis_cleanup.cjs --apply`: deleted 276 legacy `ratelimit:*:json`, EXPIRE 30d on
  445 `pending-notif-*`. dbsize 2085 → 1814. customer-*/crypto-* (payment-link store) untouched.

## Suspicious-activity alerts — DONE
- `services/securityAlertService.ts` `notifySuspiciousActivity({email,event,ip,channel})`: reuses
  `sendSecurityAlertEmail`, 6 locales (`merchant.securityAlert.{types,details,channels}` in
  locales/*/emails.json), IP + geo location rows, 1h dedup per (event, account) in Redis, no-op for
  unknown emails (no oracle). Fired from `recordOtpFailure(..., alert)` on 5-strike lockout (6 OTP
  sites, channel-specific) and from `loginRateLimiter` via new `createRateLimiter(..., onLimited)`
  hook when 20 failed logins/15min trip. Verified in-process (email SUPPRESSED by SAFE MODE).

## Exact money math — DONE (backend + frontend), zero display regressions
- Backend `utils/money.ts` (decimal.js): D/add/sub/mul/div/sum/pct/roundTo/toNumber/toFixedStr/
  toAmountStr/toBaseUnits/fromBaseUnits/splitFee/convert. Rule: merchant side rounded DOWN, fee
  absorbs remainder. Tests `__tests__/money.test.ts`.
- Codemod `scripts/codemods/money_codemod.py` (expression-aware): 652 backend + 126 frontend
  `Number(x.toFixed(n))`/`x.toFixed(n)`/`Math.round(x*10^k)/10^k` sites → toNumber/toFixedStr.
- Hand-refactored arithmetic: feeService (tier fees), settleTransaction (sats via toBaseUnits,
  gas/amount subtraction, merchant amounts rounded down), tatumApi (all transfer `amount:` strings
  now `toAmountStr` = exact + ROUND DOWN, base units via BigInt), chainVerification (admin/merchant
  split exact: merchant down / admin up, admin+merchant === received), verifyPayment, cryptoCheckout
  → new pure `controller/payment/checkoutMath.ts` (`computeCheckoutSplit`, merchant+fees ===
  customer amount; 500-case property test in `__tests__/checkoutMath.test.ts`), conversionService,
  merchantPoolSweep (balance−fee rounded down), invoiceController (cents, lines foot), taxService
  (tax = complement), feeController, feeRateService, referral credit/commission, dashboard/analytics
  sums (`sum()`), FX conversions (`mul(amount, rate)`).
- Frontend `utils/money.ts` (dependency-free BigInt decimal-string rounding): toFixedStr/toNumber/
  trimZeros/formatExact; `utils/currencyFormat.ts` formatters route through it (Intl receives the
  pre-rounded string). Tests `tests/unit/money.test.mjs` (node). 
- Verification: before/after JSON snapshots of 11 merchant endpoints byte-identical (except live
  tickers) — `scripts/audit/snap/`. BE tsc 0, FE tsc 0, eslint 0 errors, jest 657 pass (same 4
  pre-existing env-dependent suites fail).
