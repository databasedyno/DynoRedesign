## 4. ISSUE #3 — OTP TYPOGRAPHY INCONSISTENCY

### Root cause (confirmed via code inspection)
There are TWO places OTPs appear, using TWO different type systems:

| Location | Font | Look |
|---|---|---|
| **Email OTP block** (`/app/backend/utils/emailTemplate.ts` line 287, `otpBlock()`) | `'SF Mono', 'Fira Code', monospace, Arial` | Digital / monospace ✓ |
| **All web OTP INPUT boxes** (`/app/Components/UI/OtpInputPanel/index.tsx` line 680) | `UrbanistBold` (sans-serif) | Normal text ✗ |

Every OTP screen in the app funnels through `OtpInputPanel`:
- `/auth/register` (inline)
- `OtpDialog` modal — used by login (email OTP + SMS OTP), phone-only login, `AddWalletModal`, `DeleteWalletModal`, `ForgotPasswordDialog`, `EmailVerificationBanner`, `SteppedProgressPanel`, `AddContactInfo`, `AccountSetting`, `UpdatePassword`.

Fixing `OtpInputPanel` fixes all of them in one shot.

### Options presented to user (pick one)
| Option | Font | Notes |
|---|---|---|
| **3a** (recommended) | `JetBrains Mono, SF Mono, Menlo, Consolas, "Liberation Mono", monospace` | Clean modern monospace — same family used in `/documentation`, `TryItNow`, homepage code blocks. Best consistency across the whole product. |
| 3b | `Orbitron, "Share Tech Mono", monospace` | Overtly LCD-clock feel. Loud. |
| 3c | Exact email stack: `'SF Mono', 'Fira Code', monospace, Arial` | Pixel-perfect parity with the email. |

### Implementation
Only one file changes: `/app/Components/UI/OtpInputPanel/index.tsx`.

**Line 676-687** — the `& .MuiInputBase-input` sx block:
```tsx
// BEFORE
"& .MuiInputBase-input": {
  textAlign: "center",
  fontSize: isMobile ? "20px" : "22px",
  fontWeight: 700,
  fontFamily: "UrbanistBold",   // <-- change this
  padding: "0 !important",
  letterSpacing: "0.5px",         // <-- bump this slightly for the digital feel
  color: theme.palette.text.primary,
  height: "100%",
  lineHeight: inputSize,
},

// AFTER (option 3a)
"& .MuiInputBase-input": {
  textAlign: "center",
  fontSize: isMobile ? "22px" : "24px",  // slight bump — mono fonts render optically smaller
  fontWeight: 600,                        // JetBrains Mono at 700 is TOO heavy
  fontFamily: `'JetBrains Mono', 'SF Mono', Menlo, Consolas, 'Liberation Mono', monospace`,
  fontVariantNumeric: "tabular-nums",     // ensures every digit is the same width
  padding: "0 !important",
  letterSpacing: "1px",                    // digital feel
  color: theme.palette.text.primary,
  height: "100%",
  lineHeight: inputSize,
},
```

Also — **font loading**. Check `/app/pages/_app.tsx` or `/app/pages/_document.tsx` for a Google Fonts `<link>` for JetBrains Mono. If not present, add:
```tsx
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossOrigin="" />
<link href="https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@500;600;700&display=swap" rel="stylesheet" />
```

If the product prefers **not to depend on Google Fonts** (privacy/CSP), use `next/font/google` with `JetBrains_Mono` — the pattern is already used elsewhere; grep `next/font` for existing setup.

**Optional polish** — also apply the same monospace stack to:
- The email `otpBlock` (line 287 of `emailTemplate.ts`) → already `'SF Mono', 'Fira Code'`. Change to the same stack (option 3a) for perfect parity.
- The homepage `HeroV2.tsx` (line 591) and `TryItNow.tsx` (line 128) already use the same family — no change needed.
